進め方
1. アカウントと予算の準備
- 使用リージョンを決める。国内公開なら、まず東京リージョンを候補にします。
- ルートユーザーの保護やMFAなど、アカウントの基本設定を確認する。
- 月額予算と請求アラートを設定する。
- AWS料金計算ツールで、予定する構成の概算を作る。
予算アラートは料金の上限を強制するものではないので、使わないリソースを停止・削除する手順も必要です。
2. ネットワークと「NATなし」の方式を決める
FargateとRDSをVPC内に置き、インターネットから直接アクセスできないようにします。RDSは非公開にし、FastAPIのタスクからだけ接続を許可します。RDSの公開・非公開設定
NAT Gatewayを使わずFargateを非公開にする方法として、主に次の2案があります。
案	通信経路	主な特徴
VPC Endpointを使う	Fargate → ECR・S3・CloudWatch Logsなど	インターネットを経由せずAWSサービスへ接続できます。Endpointの種類によって料金が発生するので、必要なものを絞って見積もります。
タスクにパブリックIPを付ける	Fargate → AWSサービス	NAT Gatewayを避けられますが、セキュリティグループを適切に制限する必要があります。


NATなしでもAWSサービスへ接続する方法はありますが、どの方法でも追加コストが一切ないとは限りません。ECRからのイメージ取得やCloudWatch Logsへの送信などを洗い出し、この段階で費用と設定の複雑さを比べます。VPC Endpointを使った接続
3. RDSを作る
- PostgreSQLのRDSを作成する。
- RDSは非公開にする。
- 接続元はFargateのセキュリティグループに限定する。
- DB名や認証情報を決め、アプリから安全に参照できる形にする。
RDS作成後、DDLを適用してテーブルを作り、必要な初期データを用意します。RDSを停止してもストレージなどの料金は残り、停止から7日後には自動で再起動します。RDSの停止仕様
4. コンテナイメージを置き、Fargateを動かす
- ECRにバックエンド用リポジトリを作る。
- 現在のDockerfile.prodと本番用requirementsを確認してイメージを作り、ECRへ登録する。
- ECSのタスク定義に、イメージ、CPU・メモリ、環境設定、ログ出力などを定義する。
- ECSサービスを作成し、Fargateタスクを1つ起動する。
- Cloud Mapと連携し、API Gatewayがタスクを発見できるようにする。
Fargateはタスクを止めるまで、指定したCPUとメモリの稼働時間に応じて料金が発生します。Fargateの課金方式
5. API GatewayからFastAPIへ接続する
- VPC Linkを作る。
- API Gateway HTTP APIを作り、Cloud Mapのサービスへ接続する設定をする。
- APIのルートをFastAPIのパスに対応させる。
- ステージ名がFastAPIのパスに余計に付かないよう確認する。AWS資料では、必要に応じてパス変換を設定するよう説明されています。HTTP APIのプライベート接続
- API Gateway経由でログイン、一覧取得、更新などを確認する。
この段階では、API GatewayのURLを使ってバックエンド単体の接続を確かめます。ブラウザからのCookieやCORSの調整は、API疎通を確認したあとに行います。
6. S3とCloudFrontでフロントエンドを公開する
- フロントエンドを本番用にビルドし、ビルド結果をS3へ配置する。
- S3バケットを非公開にし、CloudFront経由でのみ画面ファイルを配信する。
- CloudFrontにS3とAPI Gatewayの2つを接続先として設定する。
- /api/*などのパスはAPI Gatewayへ、それ以外はS3へ送る。
- APIへのリクエストはキャッシュしない設定にする。
- 認証にCookieを使う場合、必要なCookieやヘッダーがAPI Gatewayまで届くか確認する。
CloudFrontでS3への直接アクセスを制限するには、Origin Access Control（OAC）を使う方法があります。S3オリジンの制限 CloudFrontのパスでS3とAPI Gatewayを振り分ける構成例もAWSが示しています。CloudFrontとAPI Gatewayの構成例
7. 手動の起動・停止手順を作る
公開するとき
1. RDSを起動し、利用可能になるまで待つ。
2. ECSサービスの希望タスク数を1にする。
3. FastAPIが起動し、Cloud Mapへ登録されるまで待つ。
4. API Gateway経由の動作と、CloudFront経由の画面を確認する。
5. 確認後に公開を案内する。
公開を終えるとき
1. ECSサービスの希望タスク数を0にする。
2. タスク停止を確認する。
3. RDSを停止する。
ECSは希望タスク数を変更してサービスを停止・再開できます。ECSサービスの更新 起動には数分かかる場合があるため、デモを始める直前ではなく、余裕をもって起動します。
最初に取り組む作業
いきなり全サービスを作るのではなく、最初は次の3点を確定させるのがよいです。
1. 東京リージョンを使うか
2. NATなしのFargate通信を、VPC Endpoint案とパブリックIP案のどちらで設計するか
3. ECR・CloudWatch Logs・DB認証情報など、本番で必要な接続先と設定値を整理する
特に2は、セキュリティ、月額費用、設定の難しさに影響します。ここを決めてからVPC、RDS、ECSの順に作ると、ネットワークを後から組み直す可能性を減らせます。
