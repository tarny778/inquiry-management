API01、問い合わせ登録
POST
/api/inquiries

目的：問い合わせを新規登録する。

リクエスト
- 問い合わせ職員番号
データ型VARCHAR(20)、必須、
許容する値、職員.職員番号にある値のみ、
不正な値が来た、エラーを返し登録しない
値の取得元、画面101での入力値
備考、問い合わせ当時の所属をバックエンドで取得する際に、外部キーとなる

- 受付経路
データ型VARCHAR(20)、必須、
許容する値、電話、メール、フォーム
不正な値が来た、エラーを返し登録しない
値の取得元、画面101での選択値

- 問い合わせ分類
データ型VARCHAR(30)、必須、
許容する値、分類A、分類B、分類C
不正な値が来た、エラーを返し登録しない
値の取得元、画面101での選択値
備考、問い合わせ分類マスタは、随時加除修正していく。
　　　加除修正していくための画面も設置が必要であるが、
　　　とりあえず、選択肢は固定として進めたい

- 件名
データ型VARCHAR(100)、必須、
許容する値、文字列のみ、最大１００文字
不正な値が来た、エラーを返し登録しない
値の取得元、画面101での入力値

- 緊急度
データ型数値、必須、
許容する値、1,2,3
不正な値が来た、エラーを返し登録しない
値の取得元、画面101での選択値
備考、各数値が表す緊急度の意味は、要件定義・DB設計に従う

- 受付時の処理
データ型数値、必須、
許容する値、1,2,3
不正な値が来た、エラーを返し登録しない
値の取得元、画面101での選択値
備考、各数値が表す受付時の処理の意味は、要件定義・DB設計に従う

- 問い合わせ詳細
データ型VARCHAR(1000)、任意、
許容する値、文字列、最大１０００文字
不正な値が来た、エラーを返し登録しない
値の取得元、画面101での入力値
備考、未入力を許可し、未入力ならnullとする

- 受信日時
データ型日時、受付経路がメールorフォームの場合のみ必須
許容する値、日時型の値のみ
不正な値が来た、エラーを返し登録しない
値の取得元、メールorフォームの場合、その受信日時から取得
備考、電話ならリクエストに受信日時を含めず、バックエンドで現在日時を設定する。
　　メール・フォームなら、リクエストに受信日時を含め、日時として妥当か検証する。


バックエンドの処理
### 1. リクエスト検証

リクエストの必須項目、データ型、文字数、選択可能な値などを検証する。

次のいずれかに該当する場合はエラーを返し、問い合わせを登録しない。

- 必須項目が不足している
- APIで定義していない項目が含まれている
- データ型が不正である
- 文字数が上限を超えている
- 選択肢として定められていない値が指定されている
- 受付経路と受信日時の指定が、APIで定めた条件に合致しない

例：緊急度に4が指定されている、件名が101文字である、電話受付なのに受信日時が指定されている、など。


### 2. 職員確認

リクエストで指定された問い合わせ職員番号が、職員テーブルに存在すること。
条件を満たさない場合はエラーを返し、問い合わせを登録しない。

### 3. 所属取得

問い合わせ職員番号を使用して職員テーブルを検索し、該当する職員の所属を取得する。

取得した所属について、以下を確認する。

- 所属が取得できない場合
- 所属が `null` の場合
- 所属が30文字を超える場合

いずれかに該当する場合はエラーを返し、問い合わせを登録しない。

取得した所属は、問い合わせ当時の所属として問い合わせテーブルに保存する。

### 4. 現在日時の取得

システムの現在日時を取得する。

現在日時を取得できなかった場合はエラーを返し、問い合わせを登録しない。

取得した現在日時は、登録日時、電話受付の場合の受信日時、および受付時の処理に応じた対応完了日時の設定に使用する。

### 5. 受付担当者取得

本来は、ログイン中の情シス職員を特定し、その職員番号を取得する。

ただし、開発中はログイン機能が未実装のため、リクエストから受付担当者の職員番号を受け取る。

受付担当者の職員番号を取得できない場合はエラーを返し、問い合わせを登録しない。

### 6. 受付担当者確認

手順5で取得した受付担当者の職員番号を使用して職員テーブルを検索し、以下の2点を確認する。

- 受付担当者の職員番号が職員テーブルに存在すること。
- 受付担当者の所属が「情報システム課」であること。

いずれかの条件を満たさない場合はエラーを返し、問い合わせを登録しない。

存在しない場合はエラーを返し、問い合わせを登録しない。

### 7. 問い合わせテーブルへの登録

リクエスト検証で確認した各項目に加え、以下の値を設定する。

| 登録項目 | 設定する値 |
|---|---|
| 問い合わせ当時の所属 | 手順3で取得した所属 |
| 登録日時 | 手順4で取得した現在日時 |
| 受信日時 | 受付経路が電話の場合は手順4で取得した現在日時。それ以外の場合はリクエストで指定された日時 |
| 対応完了日時 | 受付時の処理が1または3の場合は手順4で取得した現在日時。2の場合は `null` |
| 受付担当者 | 手順5で取得した受付担当者職員番号 |

上記の値とリクエストで受け取った各項目を使用して、問い合わせテーブルにレコードを挿入する。


### 8. レスポンス作成

問い合わせテーブルへのレコード挿入が成功した場合、データベースで自動採番された問い合わせ番号をレスポンスとして返す。
